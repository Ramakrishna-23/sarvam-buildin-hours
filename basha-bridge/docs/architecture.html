1 · High-Level Design

One agent process joins the call as a silent third participant. It runs two mirrored half-pipelines (STT → Translate → TTS) gated by a half-duplex turn manager, and only escalates from silent monitoring to active mediation when drift is detected.

3 · Detailed Workflow

3.1 Session startup & language lock

  1. Room created per tripcustomer & driver join via role links; agent auto-joins as 3rd participant, publishes (silent) audio track, subscribes to both parties.
  2. Passive listening beginsper-participant streaming STT opens; agent state = PASSIVE_MONITOR; no speech output.
  3. First utterance bufferedaudio between START_SPEECH/END_SPEECH is buffered and sent to REST STT with language_code=unknown → detected language + confidence; /text-lid re-checks the transcript.
  4. Pair lockafter 2 consistent utterances per side, the language pair is locked and both streaming STT sessions restart with fixed language codes. Same language on both sides → agent stays passive forever.

3.2 One translated turn (ACTIVE_MEDIATION, e.g. driver → customer)

  1. Capturedriver speaks Kannada; START_SPEECH → turn manager enters CAPTURING(driver); partial transcripts stream in.
  2. EndpointEND_SPEECH + ~0.5 s debounce → utterance final; state → PROCESSING.
  3. Protect entitiesOTP regex lock (digits never translated), glossary terms swapped for placeholders; place names routed to /transliterate instead of translation.
  4. Translate per sentenceIndic-aware sentence split (। . ? !) → parallel mayura:v1 calls (concurrency 2, order preserved), placeholders restored after.
  5. Speakfirst translated sentence goes to bulbul:v3 WS immediately (fixed “driver” voice, hi-IN) while later sentences are still translating; state → SPEAKING; customer hears original at ~20% gain underneath.
  6. Update brain (async)turn appended to rolling bilingual memory; one strict-JSON call to sarvam-105b-conversations updates drift signals + slots — off the audio critical path, allowed to lag one turn.
  7. Yieldsend_completion_event fires → state → IDLE; the mirrored pipeline handles the customer's reply identically.

3.3 Barge-in (any time during SPEAKING)

  1. Listener starts talkingSTART_SPEECH arrives from the party currently hearing playback.
  2. Cut playback locallystop publishing audio, drop queued TTS chunks — Bulbul has no server-side cancel, so this is entirely client-side.
  3. Rotate TTS socketclose the active TTS WS; promote the pre-warmed spare (one per direction) to hide reconnect latency.
  4. Capture the interrupterturn manager → CAPTURING for the interrupting party; their STT never stopped, so nothing is lost.

3.4 Drift detection & escalation ladder

Language mismatch alone ≠ intervention. Drift = mismatch + failed comprehension or stalled task. Hybrid: hard rules in code, soft signals in code, plus a bounded LLM classifier — {drift, evidence[], task_progress, frustration, safety} via strict JSON schema.

3.5 Mediation actions (deterministic)

The LLM never free-drives the call. It picks from an allowed action set; the turn manager enforces who hears what: ASK_RIDER_LANDMARK · ASK_DRIVER_LOCATION · CONFIRM_WITH_DRIVER · CONFIRM_WITH_RIDER · SUMMARIZE_AND_EXIT · SAFETY_ESCALATE. Tracked slots: pickup_point · landmark · driver_location · eta · otp_exchanged · blocker · agreed_next_action. Low classifier confidence, disputes, or “agent, tell him…” route one call to the Big Reasoning Agent (sarvam-105b), whose reply is constrained to the same action set.

5 · Build Phases (each ends demoable)

Phase 0~1 h

Scaffold repo, env (SARVAM_API_KEY, LiveKit creds), fixture WAVs (hi/kn incl. OTP + place name). Exit: --check validates Sarvam key + LiveKit join.

Phase 1~2–3 h

Sarvam client layer tested offline against fixtures: STT WS, TTS WS (keepalive + spare socket), translate (splitter + glossary), detect, chat (strict JSON). Exit: WAV → transcript → native-script translation → audible TTS; doubles as latency benchmark.

Phase 2~2–3 h

One half-pipeline (kn→hi) live over LiveKit, hardcoded pair, sentence-streamed. Exit: speak Kannada on one device, hear Hindi on the other < 2.5 s.

Phase 3~2 h

Mirror pipeline B, half-duplex turn manager FSM, barge-in, distinct voices per direction. Exit: natural back-and-forth; interrupting the agent works.

Phase 4~1 h

First-utterance language detection + pair lock; same-language → stay passive. Exit: cold start, agent figures out hi/kn itself.

Phase 5~3–4 h

Main agent: memory, OTP lock + transliteration passthrough, slots, hybrid drift, escalation ladder, allowed-action mediation, Big Reasoning slow path. Exit: scripted failing conversation → offer → mediate → slots filled → bilingual SUMMARIZE_AND_EXIT.

Phase 6~2 h

Demo polish: live transcript UI, escalation badge, slot panel, low-volume original mix, latency ticker, dry runs + fallback video.
