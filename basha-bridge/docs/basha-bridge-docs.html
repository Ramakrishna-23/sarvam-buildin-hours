1. Vision & product behavior

A live WebRTC-based AI mediator that silently monitors a two-person conversation (demo: rider ⇄ driver pickup coordination), detects communication drift, and intervenes only when the task is actually breaking down. It is a task mediator, not a translator.

No pre-assumed languages Silent monitor first Mismatch ≠ drift Escalation ladder, not binary LLM picks from bounded actions WebRTC, not push-to-talk
PASSIVE_MONITOR→ WATCH→ OFFER_HELP→ ACTIVE_MEDIATION→ RESOLVED→ PASSIVE_MONITOR

Emergency path from any state → SAFETY_ESCALATION.

3. Sarvam voice stack (researched Aug 2026)

ModelIDRoleKey facts
Saaras v3saaras:v3-realtimeSTT23 langs, language_code=auto, live partials, ms-tunable VAD, config.update mid-call, 8/16 kHz PCM only, stream_type=fast for agents
Bulbul v3bulbul:v3TTS11 langs, 30+ voices, <250 ms first-byte via WS, ≤500 chars/msg sweet spot, native script only, no server-side cancel
Sarvam-105B Conversationssarvam-105b-conversationsMediator LLMtuned for real-time dialogue; strict JSON ⚠️ verify (fallback sarvam-105b)
Sarvam-30Bsarvam-30bDrift classifier64K ctx, cheaper/faster — the hot path fires every few turns
MayuramayuraTranslatemodern-colloquial, output_script=fully-native
Why raw Model APIs, not Sarvam Voice Agents: the managed runtime assumes one-user ↔ one-agent and owns the turn loop; our silent-observer + two-party + custom escalation cannot be expressed there. We borrow its patterns (fast stream type, VAD barge-in), not its runtime.
Latency budget: STT partial ~150–300 ms · VAD end ~300–400 ms · drift (30b) ~200–400 ms · mediator (105b-conv) ~400–800 ms · Mayura ~150–300 ms · TTS TTFB <250 ms → ~1.2–2.0 s speech-to-speech. Levers: LLM emits target-language text directly (drop Mayura hop); stream TTS from first sentence.
Cost: STT ₹30–45/hr × 2 continuous streams ≈ ₹60–90 per session-hour vs ₹100 free credits. TTS ₹30/10k chars. Rate limits are per-account token-bucket; WS concurrency is a separate cap — we open 4 sockets/session.

4. Session & transcript schema (LLD §2–3)

  "livekit_room": "bb-s_8f2c",
  "state": "PASSIVE_MONITOR",
  "drift": { "score": 0.0, "hard_trigger": null, "history": [...] },
  "participants": { "rider": Participant, "driver": Participant },
  "transcript": [ TranscriptTurn... ],       // append-only, finals only
  "task": TaskState,
  "turn_manager": {...},
  "metrics": { "stt_ms": [], "llm_ms": [], "tts_ttfb_ms": [] }
}

Participant.lang_profile = {
  "detected": [ {"lang":"hi-IN","count":7,"avg_conf":0.91} ],
  "primary": "hi-IN",     // stable after ≥2 finals same lang, conf ≥ 0.7
  "stable": true
}

TranscriptTurn = {
  "turn_id": 14, "speaker": "driver",
  "text": "ನಾನು ಗೇಟ್ ಒಂದರ ಹತ್ತಿರ ಇದ್ದೇನೆ",   // native script
  "text_en": "I am near gate one",           // lazy, batched translate
  "lang": "kn-IN", "confidence": 0.88,
  "is_question": false, "ts_start": 132.4, "ts_end": 135.1
}

Partials live in a scratch buffer and stream to UIs; only finals enter the transcript. text_en is filled in one batched call over the last-N window when the drift LLM or mediator runs — not per turn.

6. Sarvam API contracts (LLD §5)

Auth everywhere: header api-subscription-key. ⚠️ = verify exact key names against live API reference before coding.

STT realtime

wss://api.sarvam.ai/speech-to-text-realtime/ws?language_code=auto&model=saaras:v3-realtime

→ {"type":"config","stream_type":"fast","mode":"transcribe",
   "input_audio":{"encoding":"linear16","sample_rate":16000},
   "vad":{"silence_duration_ms":400,"min_speech_duration_ms":120}}   ⚠️
→ {"type":"audio","data":"<b64 pcm, 100ms frames>"}
← speech.start / speech.end / transcript.partial / transcript.final
→ {"type":"config.update", ...}   // PASSIVE→ACTIVE: silence 400→300ms, no reconnect

Drift classifier — sarvam-30b, strict JSON

{ "comprehension_failure": bool, "repeated_question": bool, "contradiction": bool,
  "frustration": bool, "task_progressing": bool, "safety_concern": bool, "confidence": 0.0 }

Mediator — sarvam-105b-conversations, strict JSON

{ "action": "ASK_RIDER_PICKUP_POINT | ASK_RIDER_LANDMARK | ASK_DRIVER_LOCATION |
             ASK_DRIVER_FEASIBILITY | ASK_DRIVER_ETA | CONFIRM_WITH_RIDER |
             CONFIRM_WITH_DRIVER | SUMMARIZE_AND_EXIT | SAFETY_ESCALATE",
  "target": "rider|driver|both", "utterance_en": "≤25 words",
  "slots_update": {...}, "task_complete": false }

The app narrows the schema enum to the currently-allowed action set and validates the response; one re-prompt, then a deterministic scripted fallback.

TTS — bulbul:v3 WS

wss://api.sarvam.ai/text-to-speech/ws?model=bulbul:v3
→ {"type":"config","speaker":"<per-lang>","target_language_code":"hi-IN",
   "pace":1.0,"output_audio_codec":"mp3","speech_sample_rate":24000}
→ {"type":"text","text":"<native script only, ≤500 chars>"} → {"type":"flush"}
Barge-in: no server-side cancel exists. Browser stops playback locally; server abandons the utterance and drops + reopens that TTS socket (warm pool per participant+language).

7. Task slot schema (LLD §6)

slots: pickup_point · landmark · driver_location · rider_location · eta ·
       otp (protected) · blocker · agreed_next_action
required_for_resolution: [pickup_point, eta, agreed_next_action]
resolution_rule: all required filled AND confirmed_by includes both roles
Entity protection: protected slots (OTP, gate numbers, vehicle no., amounts) are regex-extracted from the source turn and spliced into utterances verbatim — never rewritten by translation or the LLM.

8. Drift engine (LLD §7)

#SignalConditionΔ
S1lang_mismatch_stableboth profiles stable & different (once)+2.0
S2low_stt_confidencefinal conf < 0.6+1.0
S3explicit_confusionphrase table hit (per-language YAML)+3.0
S4repeated_questionfuzzy sim > 0.8 vs own prior question+2.0
S5slots_stalled≥6 turns, no required slot filled+2.0
S6contradictionslot conflicts with confirmed value+2.0
S7silence_after_question>8 s+1.0
S8frustrationkeyword table hit+2.0
—decayclean turn−1.0 (floor 0)
score ≥ 3 → WATCH        (classifier polling every 3rd turn)
score ≥ 6 → OFFER_HELP   only if 30b confirms (comprehension_failure OR
                          !task_progressing, conf ≥ 0.6)
score ≥ 8 → ACTIVE_MEDIATION
Hard: help button → OFFER_HELP · safety words → SAFETY_ESCALATION ·
      3 consecutive S3/S4 turns → ACTIVE_MEDIATION
Veto: classifier task_progressing=true @ conf ≥ 0.8 → score −2.0

9. Turn manager — ACTIVE_MEDIATION (LLD §8)

┌─────────────┐ grant(X)  ┌──────────────┐ final from X ┌────────────┐
│ AGENT_SPEAK │ ────────► │ WAIT_FOR(X)  │ ───────────► │ PROCESSING │
└─────▲───────┘           └──────┬───────┘              └─────┬──────┘
      │        timeout 12s: re-ask once, then other side      │
      └──────────────── next utterance ◄──────────────────────┘
  • Allowed-action set computed from task state; the LLM chooses within it.
  • Non-granted speaker's finals are transcribed and shown, but not fed to the mediator.
  • Barge-in from the granted speaker = early answer, not an error.
  • Exit: task_complete + app-verified resolution rule → SUMMARIZE_AND_EXIT → RESOLVED → PASSIVE_MONITOR (score reset, S1 suppressed 10 turns).

14. Key code sketches

Resampler + framer

class Framer:  # 48k float32 → 16k int16 mono, 100ms (1600-sample) frames
    def push(self, pcm48, channels):
        mono = pcm48.reshape(-1, channels).mean(axis=1) if channels > 1 else pcm48
        ints = np.clip(soxr.resample(mono, 48000, 16000) * 32767, -32768, 32767).astype(np.int16)
        self.buf = np.concatenate([self.buf, ints]); out = []
        while len(self.buf) >= 1600:
            out.append(self.buf[:1600].tobytes()); self.buf = self.buf[1600:]
        return out

Mediator with schema-narrowed enum

async def next_move(sess):
    allowed = sess.turn_manager.allowed_actions()
    schema = mediator_schema(allowed)          # enum narrowed to allowed set
    for _ in range(2):
        r = await chat(MEDIATOR_MODEL, build_prompt(sess, allowed),
                       response_format={"type":"json_schema","json_schema":schema},
                       temperature=0.2, max_tokens=200)
        move = Move.parse(r)
        if move.action in allowed: return move
    return deterministic_fallback(allowed)     # scripted question, never stuck

TTS warm-socket pool + barge-in

class TtsPool:   # one warm WS per (participant, language)
    async def speak(self, role, lang, text_native, on_chunk):
        ws = await self._get_or_open(role, lang)
        await ws.send({"type":"text","text":text_native}); await ws.send({"type":"flush"})
    async def abandon(self, role, lang):       # barge-in: no server cancel
        await self._close(role, lang)          # next speak() reopens

Frontend: MP3 chunks → MediaSource append; stop() detaches buffer instantly. Browser RMS-threshold VAD fires barge_in during agent playback.

Classifier (30b)

"You judge whether a two-person service conversation is progressing. Answer only the JSON schema. Do not infer problems that aren't evidenced." + last-8 en turns, slots, language profiles.

Mediator (105b-conv)

"You are a calm pickup coordinator. One short question or confirmation at a time, ≤25 words, no explanations. Choose only from ALLOWED_ACTIONS. Never alter OTPs, gate numbers, vehicle numbers."

16. Testing strategy

  • Replay tests: record real STT final sequences in M1 → drift rules, turn manager, task store are pure functions over tests/replays/*.jsonl — no audio, no network.
  • Contract spikes: the two M1 spike scripts stay runnable to re-verify API shapes after any Sarvam changelog bump.
  • Latency harness: every Sarvam call timed → /session/{id}/metrics p50/p95, checked each rehearsal.
  • Chaos toggles: fake STT drop / TTS failure via env flags → prove F1–F5 engage.

18. Definition of done (MVP)

  • Two browsers, live WebRTC call, no push-to-talk
  • Live bilingual transcript with partials + per-speaker language badges
  • Agent silent through a working conversation (no false positive ×3 rehearsals)
  • Scripted confusion → OFFER_HELP → ACTIVE_MEDIATION with targeted audio
  • Slots fill → bilingual summary → RESOLVED → back to silent
  • Barge-in stops agent audio < 300 ms
  • p95 speech-to-speech ≤ 2.5 s on demo hardware
  • All five fallback flags tested once
